# AGENTS.md — X-WAM

Post-training (SFT) code for X-WAM, a 4D world-action model built on Wan2.2-TI2V-5B. No test suite or linter is configured — verification is done by running the data pipeline and short training smoke tests.

## Environment

- Python 3.10 venv at `.venv/` (uv-managed). Run everything with `.venv/bin/python`, never system python.
- `pyproject.toml` pins the tsinghua PyPI mirror and pulls torch from the cu129 index. flash-attn is an optional extra: `[tool.uv] no-build-isolation-package` is set because its build needs the already-installed torch.
- `pandas` is intentionally absent; read parquet with `pyarrow` (`table.column(...).to_pylist()`).
- `tensorboard` is required by the default TensorBoardLogger even when using wandb.

## Training

- Full command lives in `cmds/train_xwam.sh`
- **Do not run on a single GPU**: DeepSpeed optimizer states for the 5B model OOM one H20 (96G). Use all 8 GPUs even for smoke tests (`num_training_steps=2 save_interval=100000`).
- Config = `configs/model/wan22_5b_sft.yaml` merged with `configs/data/{dataset}.yaml` (chosen by `dataset=`). Any field is overridable via OmegaConf dot notation on the CLI.
- **`wan_checkpoint_dir` must be overridden** on the CLI: the yaml default points to `./checkpoints/wan22_5b/` but weights live in `./checkpoints/Wan2.2-TI2V-5B/`.
- The pretrained SFT checkpoint path `checkpoints/pretrained/checkpoints/last.ckpt` (a directory containing `checkpoint/mp_rank_00_model_states.pt`) is loaded automatically.
- Logging cadence: wandb/TB metrics flush every `log_interval` (20) steps; validation every `val_interval` (2500) steps.

## Data pipeline (LeRobot → X-WAM)

Raw collections in `raw_data/<task>_v1` are LeRobot v2.x format and **cannot be consumed directly**. Convert first:

```bash
.venv/bin/python scripts/convert_raw_data.py --src raw_data/<task>_v1 --dst sft_datasets/<task>
.venv/bin/python scripts/compute_stats.py --dataset-root sft_datasets/<task> --action-skip 1
```

Then create `configs/data/<task>.yaml` and paste the q01/q99 values from `sft_datasets/<task>/quantile_pretrain.yaml` into its `statistics:` section (copy the structure from `configs/data/place_fruits.yaml`).

Hard-won quirks:

- **decord cannot decode AV1** — raw RGB (`videos/chunk-000/.../*.mp4`, AV1) must be transcoded to H.264. The converter does this.
- **decord silently destroys FFV1 gray16 depth** (returns collapsed uint8 0–4). Depth is decoded via ffmpeg rawvideo `gray16le` and linearly mapped to 8-bit meters (`--depth-max-m`, default 3.0).
- **X-WAM is end-effector space only**. The 14-dim joint state/action goes through `scripts/piperx_fk.py` (Piper-X MDH FK) to produce `ee_pos`/`ee_rotm`/`gripper_pos` per arm. Gripper stays in raw jaw-radians; quantile normalization handles the scale.
- Exactly **3 camera views** are required — `runners/xwam_runner.py` hardcodes `num_views = 3`. Views are named by the episode JSON `observations` keys, sorted alphabetically; `type` must be `static` or `dynamic`.
- `metadata.json` (`{episode_key: num_frames}`) is auto-generated by `RobotDataset` if missing, but `convert_raw_data.py` writes it anyway.
- Episode JSON layout reference: `README.md` ("Data Structure"); loader: `data/robot_dataset.py` (delta-EE action path; `raw_actions` is the RoboCasa-only alternative with gripper sign negated).

## Real-robot deployment (`deployment/`)

- `deployment/websocket_policy_server.py` — openpi-style websocket server (msgpack wire format, one binary frame per request; `{"command": "get_config"}` returns metadata). Client may use `openpi_client.WebsocketClientPolicy` directly or `deployment/lerobot_client_example.py`.
- `deployment/xwam_policy.py` — inference wrapper. Accepts `images` ([V,H,W,3] uint8, 3 views in **alphabetical order** = fixed_front, left_arm, right_arm) plus either `proprios` ([16] raw EE) or `agent_pos` ([14] raw joints, FK'd server-side). Preprocessing mirrors `evaluation/policy_server.py` (resize→center-crop→resize, quantile stats from the exp `config.yaml`).
- Returns `actions` [Ta,14] **delta EE** (relative to request-time pose, global frame) and `proprios` [Tp,16]; robot side accumulates deltas itself (reference impl: `evaluation/X-WAM/deploy_policy.py::compute_future_poses`).
- Loading a checkpoint is expensive — the policy is a separate process, not part of training scripts.
